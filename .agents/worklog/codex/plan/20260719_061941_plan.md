# Goal

P1-F1-T5 の8 writer SQLite load harnessを実装し、hx/mixed 各600秒の隔離DB実測で NFR-03 を判定し、結果文書とCI smokeを PR 経由で main へマージする。

# Scope

task a007 の allowed filesに限り、`db/load-test.sh`、`ci/test_sqlite_load.sh`、CI step、`docs/reference/sqlite-load-test.md` と a007 証跡を扱う。

# Assumptions

- harness は既存 `db/migrate.sh` と Python標準ライブラリ `sqlite3` を再利用し、dependencyを追加しない。
- `--writers` 既定8、`--duration` は正整数、`--profile` は hx/mixed のみとする。
- 各 writer は10ms pacing（最大約100 writes/sec）で、開始・終了 monotonic clockを共有する。
- mixed は8 writers中1 writerが同等schemaの模擬 agmsg messages、残り7 writersが hx eventを書く。
- busy_timeout は5000ms、WAL、synchronous=NORMALを固定し、busy/locked は最大10回 retry 後に permanent failure と数える。
- 2本の600秒 run は互いに独立した repository外 scratch DBで直列実行する。

# Design

shell entrypointが引数とDB安全境界を検証し、migration後に埋込みPython coordinatorを起動する。8 OS processesは writer別 TSVへ成功可否、latency ms、retry数を記録する。親processが期待/実件数、writer別件数、p50/p95/p99、busy retry、permanent failure、throughputを集計し、欠損0・permanent failure0・p95<100msを NFR-03 PASS とする。

# Tests

- 実装前に CI smoke が `db/load-test.sh` 不在で失敗することを確認する。
- hx/mixed 各8 writers ×20秒で件数一致、deadlocks 0、p95<100ms、WAL、busy_timeout=5000を確認する。
- 不正 option、既存DB、`.agents`配下DBを拒否する。
- shell syntax、ShellCheck、既存 rules/migration/task-ledger testsを通す。
- hx/mixed 各600秒を直列で実測し、出力全文と scratch DB cleanupを検証する。
- PR の CI green を `gh` で確認する。
