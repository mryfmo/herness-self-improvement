# Goal

P1-F1-T3 の `hx_` telemetry schema、冪等 migration、隔離DBテスト、schema reference、CI を PR 経由で main へマージする。

# Scope

task a005 の allowed filesに限り、2 migration SQL、`db/migrate.sh`、`ci/test_migrations.sh`、`docs/reference/telemetry-schema.md`、`.github/workflows/ci.yml` と a005 証跡を扱う。

# Assumptions

- a004 は acceptance 済みで、`main` と `origin/main` は `bd8aa9b3d8faf0ebb9ca6afa6bfe4bed1b905d9c` で一致している。
- SQLite 3.51.0 は FTS5 対応で、実装は sqlite3 CLI と POSIX shell だけを使う。
- migration/test は注入された system temporary database path だけを使い、実運用 agmsg DB に schema を適用しない。
- WAL/busy timeout の恒久値と agmsg 同居/分離は F1-T5 後の残存決裁であり、本taskでは接続時設定だけを行う。

# Design

`hx_schema_migrations` ledger を wrapper が作成し、up/down は `IF NOT EXISTS` / `IF EXISTS` と transaction で冪等化する。6 base tables、prompts/skill_runs の external-content FTS5 tablesと同期 triggers、audit UPDATE/DELETE拒否 triggersを作る。test は一時DBで up→up→down→down→up、FTS検索、FK、append-only、WAL/busy timeout、schema文書名整合を検証する。

# Tests

- 実装前に `ci/test_migrations.sh` が migrate script 不在で失敗することを確認する。
- up/up/down/down/up の各段で migration status、table/virtual table、trigger の存在/不存在を確認する。
- prompt と skill run を挿入し、両 FTS5 tableが検索可能であることを確認する。
- audit の UPDATE/DELETE と orphan FK が拒否されることを確認する。
- WAL と connection busy_timeout=5000 を確認する。
- up DDLに現れる全 `hx_` table名と ledger が schema文書にあることを確認する。
- PR の `ci` check が green であることを `gh pr checks` で確認する。

# Open Questions

agmsg DB 同居/分離と WAL/busy timeout の恒久値は P1-F1-T5 の負荷試験後に決裁する。
