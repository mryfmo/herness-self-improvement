# Goal

P1-F1-T4 の task ledger schema、DB強制の状態機械、冪等 CLI、隔離DB test、schema reference、CI を PR 経由で main へマージする。

# Scope

task a006 の allowed filesに限り、migration 0002、既存 migration runner、`db/hx-task.sh`、`ci/test_task_ledger.sh`、schema reference、CI step と a006 証跡を扱う。

# Assumptions

- a005 は acceptance 済みで、main に migration 0001 と `db/migrate.sh` が存在する。
- CLI は `create <idempotency-key> <workplan-ref> <branch> <done-criteria> [max-attempts]`、`claim <task-id> <owner>`、`start <task-id>`、`progress|done|fail|block <task-id> <payload>`、`requeue <task-id> [timeout-minutes]`、`show <task-id>`、`list` とする。
- timeout 判定は progress でも更新する `updated_at` を基準とし、既定15分とする。
- requeue は attempts を1増やし、新値が max_attempts 以下なら queued、超えたら failed に固定する。
- test は注入された system temporary database path だけを使い、実運用 agmsg DB に適用しない。

# Design

migration 0002 に `hx_tasks`、`hx_task_messages`、検索用2 indexes、状態遷移 trigger を置く。状態遷移は DB trigger を信頼境界とし、CLI は transaction と条件付き UPDATE で操作する。create は unique idempotency key の conflict を無変更として既存 task_id を返す。既存 runner は0001→0002で up、0002→0001で downする最小拡張とし、a005 の status contract を維持する。

# Tests

- 実装前に `ci/test_task_ledger.sh` が CLI 不在で失敗することを確認する。
- queued→claimed→running→done/failed/blocked の各正常パスを検証する。
- queued→running、done→claimed と DB direct update の不正遷移を拒否する。
- idempotency key 重複 create が同一 task_id を返し、row/message を重複させない。
- timed requeue と attempts 上限超過時の failed 固定を検証する。
- workplan_ref、branch、done_criteria、owner、payload、整数引数の欠落・不正を拒否する。
- 0001/0002 の up/up/down/down/up と既存 CI を通す。
- PR の CI green を `gh` で確認する。
